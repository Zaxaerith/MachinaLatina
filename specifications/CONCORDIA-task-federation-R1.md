# CONCORDIA Task Federation R1 — Bounded cross-domain computing
> FUTURE SCENARIO / DRAFT / NOT CANON · 2026-11-26. Candidate 2045–2050 logical contract, not a deployed distributed OS, secure transport, consensus implementation or working agent runtime.

## 1. Independent domains
A domain is an independently administered host or service cluster with its own principals, resources, scheduler and trust policy. Domain identity must be authenticated by an external future trust mechanism; a numeric label or COS display name is not authentication. ORDO-N, PARTES and CVSTOS retain their native resource controls. CONCORDIA coordinates authorized services, not a global kernel, virtual address space or cache-coherent shared memory. MENTIS proposes tasks; a trusted local coordinator admits work. No model can enlarge authority. Memoria handles and TESSERA handles remain local, never sent as remote grants.

## 2. Bounded remote work
This profile extends the design ideas of MENTIS Agent Task R1 without changing that local sequential contract. A coordinator selects a finite acyclic graph of at most 32 steps, with immutable plan revision, pinned input identities, service/profile revision, output schema, predecessors, allowed receiving domains, data disclosure scopes, per-step maximum admitted calls/bytes/compute units, and local monotonic deadline. Compute units must have a declared metering definition per service; do not equate tokens, CPU seconds and joules. Independent eligible steps may run concurrently; dependants start only after validated predecessor output. No recursion, automatic subcontracting, arbitrary shell access or physical actuation in this profile.

A remote request identity is (authenticated coordinator domain, coordinator epoch, task ID, plan revision, step ID, attempt ID), scoped to a declared service. IDs never reused in that scope. Transport retransmission retains the same attempt identity and canonical request binding; a deliberate new attempt has a new ID and consumes a new reservation. A remote domain independently authenticates the caller, checks its own policy, validates exact inputs and operation, and accepts or rejects. Scope binds receiving domain, resources/revisions, operation, output destination and limits; no transferable bearer grant is defined. Authorization to read locally does not imply authorization to disclose remotely. No transitive delegation or onward transfer in R1. A coordinator may reserve each remote budget before admission and charge it conservatively until reconciled, including uncertain outcomes; restarting a model does not refill budget.

## 3. Receipts and failure
Logical remote states: NOT_ADMITTED, ACCEPTED, RUNNING, COMPLETED, FAILED, CANCELLED, UNKNOWN. COMPLETED means a service reports completion, not that result is scientifically valid. Receipt binds request identity, actual service/profile, pinned input identities, output identity, status, usage, and relevant evidence; authentication and canonical serialization are prerequisites, not specified. Coordinator verifies binding and access, records late results separately and never treats a timeout as proof of nonexecution. Reject conflicting request bindings for reused attempt identity. Durable duplicate suppression and outcome lookup are prerequisites for reliable retransmission; absent them, stop rather than assume at-most-once. Network partition can prevent cancellation or revocation from reaching a remote node; bytes already disclosed cannot be recalled. On reconnection, reconcile status and grants before accepting new work. No global clock, exactly-once execution or distributed transaction is promised.

Remote INSPECT/COMPUTE/STAGE may create private service records and output artifacts but cannot modify user publication targets. Resource cleanup and private retention follow separately agreed policy. Final publication is local, using the existing MENTIS compare-and-set contract with current grant and exact staged result approval. If local target revision changed, return CONFLICT. Remote side-effecting writes and multi-domain commits are excluded. The partition policy is fail-closed for new work requiring unavailable authority; local offline work with valid local grants remains possible.

## 4. Paper fixture
A local ORDO-N workstation coordinates an ORBIS report. Steps: (1) inspect pinned tile revision locally; (2) send a separately authorized 4 MiB derived input to scientific domain S for a pure calculation; (3) in parallel send a separate approved 2 MiB input to visualization domain V; (4) validate both receipts and stage local report; (5) obtain approval and compare-and-set publish. Illustrative disclosure budget 8 MiB; reserve 6 MiB, leaving 2 MiB. If S times out, retain its 4 MiB reservation until reconciled, do not blindly resend to another service or publish an incomplete report. If V returns but S is unavailable, task waits within deadline or fails with explicit uncertainty. Even if remote computation succeeds, target revision mismatch prevents publication. This is a synthetic workflow, not actual ORBIS data or execution.

## 5. Boundaries
RETE-00/R1 is a fetch-only profile; authenticated remote admission, grants, canonical requests, status lookup, receipts, revocation and transport are all future protocol work. STEMMA digest suite and FASCICVLVS signature format remain open; symbolic references are not cryptographic proof. No deployment, latency guarantee, global scheduler, consensus protocol, native ABI or implementation.
