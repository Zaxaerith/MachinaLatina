# Three Operating-System Families, 2005–2015
## ORDO-N、PARTES、CVSTOS：三种候选系统哲学

> **DRAFT / 架空操作系统设计研究。** 此处没有已经实现的微内核、文件系统、驱动、ABI 或二进制兼容承诺。名称未经古典语校订。此前的 Ordo Operum 是现代 Python 宿主监控器测试模型，**不是已在架空年代发布的客体操作系统**。

## 1. 不同软件遗产意味着不同的内核边界

| 家族 | 候选市场 | 合理的核心接口 | 对架构的要求 |
| --- | --- | --- | --- |
| ORDO-N | Nova-derived PC、服务器 | 进程 + 字节流 + 命名文件 | 字节寻址、后继 32/64 位 ISA；不默认 Nova-N1 二进制兼容 |
| PARTES | Sextaria 学术工作站 | 带类型的记录服务 + 消息传递 | 可以保留 48 位科学 ABI，但不强制要求 48 位现代 CPU |
| CVSTOS | 嵌入式、手机 | 受限能力与进程隔离、节能服务 | 由低功耗技术决定指令集，不能直接沿用 Sextaria |

这些模型不要求三个系统完全独立实现。它们可能借用共同用户态库、编译器、设备驱动接口或 COS 文字服务，但这不意味着共享内核和可执行文件。

## 2. 一份科学文档怎样在三系统中打开？

文件的层次建议定义为：

1. 原始容器字节（必须保留原始编码/校验和）；
2. 文件内容类型（纯 CVL-68、COS 文档、NODVS 类型化记录、数值数据等）；
3. 声明的解码器和版本；
4. 解析后的文本、记录或者科学数值；
5. 由 TABVLA 式 GUI 或其他应用完成的字形排版与输出。

ORDO-N 可能把上述全部放进字节流文件 + 用户态元数据；PARTES 可能在用户态/服务层直接以记录身份和类型句柄工作；CVSTOS 为了权限控制或节能，可能只让应用通过受保护的文档代理访问其共享文件。

**不要在这一步把所有差异消灭：** 同一份 NODVS 文献能被多个系统读取，并不代表内核使用同一套文件 API。

## 3. 四个不可混为一谈的兼容性等级

| 层次 | 示例 | 非保证项 |
| --- | --- | --- |
| 文档兼容 | COS 身份一致，CVL-68 能被有诊断地转码 | 相同字体或页面版式 |
| 源码兼容 | MODVLA 类模块能在两套 OS 上编译 | 相同对象文件/ABI |
| 应用 API 兼容 | 文件、网络、设备接口通过适配器实现 | 相同特权分级与执行时序 |
| 二进制兼容 | 指令、装载格式、动态链接、系统调用和 ABI 明确一致 | 仅凭同一家族名自动实现 |

Sextaria 的 F48 精度与指令集从未在前十五阶段完成；本研究不能倒过来宣称现代 PARTES 已使用某种确定的 48 位对象 ABI。

## 4. ORDO-N 的字节流传统

经济动机来自低价 Nova 微机及服务器。一个候选系统可采用通用进程、虚拟地址、用户/内核隔离、路径文件和字节流设备。优势：工具组合、简单文件读写、源代码移植门槛低。

代价：COS 字符不等于字节，磁盘文件中可能有多个字符格式；旧 CVL-54 打包记录不能靠普通字节读取还原语义。用户态编码 API 和类型化文件元数据必须显式存在。

**拟议的拉丁式 API 名称**（概念演示，不是编译器可识别的调用）：

    APERIRE(documentum, modus) -> handle
    LEGERE(handle, buffer, n) -> count
    SCRIPTVRA(handle, bytes, n) -> count
    CLAVDERE(handle) -> status

这些名称只用于说明技术接口必须规定数据是原始字节、COS 字符序列还是结构化记录；它们的真实古典拉丁适切性仍待讨论。没有规定系统调用号、返回寄存器、错误码或可编译语法。

## 5. PARTES 的类型化记录传统

科学软件历史往往关注记录长度、数据单位和浮点精度。一个研究性 **PARTES** 内核可能只保留地址空间、调度、消息传递和最小资源句柄，文件系统、网络服务、文档转换与排版在可独立升级的用户态服务中运行。

这听起来类似现实微内核，却不代表我们的架空世界已经独立发明现代现实所有微内核最佳实践。性能问题必须明确：记录与消息在服务之间传输会有复制、上下文切换、验证与缓存成本，昂贵的科学数组可能需要共享页、DMA 或能力令牌来避免重复搬运。

提议的消息至少携带类型标签、长度、编码、数值格式以及权限/来源信息。**消息的虚构字段不意味着网络协议直接使用了 OMR1**；Ordo 只是现代研究模拟器，不是历史字节标准。

## 6. CVSTOS 的移动安全与功耗传统

移动设备可能拥有完全不同于 Nova-N1、Sextaria 的低功耗 CPU。即使手机运行相同的 SERMO 文档客户端，也不代表共享服务器的原生机器码。

移动系统特别需要：
- 每应用隔离的身份和存储目录；
- 摄像头、定位、麦克风、通讯设备的访问授权；
- 后台任务、电池、无线网络与屏幕休眠策略；
- COS 多语言字体与输入法服务；
- 能否安装未经厂商批准的软件，以及启动镜像的签名策略。

开放源码可提高审计能力，但不能自动提供解锁启动链、硬件固件和网络服务的自由。反过来，强制签名也不等于系统完全不能有可审核的自由软件组件；必须说清具体执行权与更新权限。

## 7. 待定的系统设计选择

- 进程还是记录服务：哪一层负责字符转换？
- 字节流、记录流能否以不破坏两者语义的方式共存？
- COS 标识符如何存储为安全文件名，怎样处理 Latin/Greek 同形异码？
- 软件包的架构标签是 N1、Nova Minor、Sextaria、通用后继 64 位，还是 OS API 等级？
- 消息系统中数值精度/单位/端序如何描述？
- 手机离线 NODVS 缓存如何处理权限和跨平台签名？
