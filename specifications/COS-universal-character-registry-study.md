# COS — Codex Omnium Scripturarum
## 全球字符身份登记簿与 CVL-68 历史字节的分离

> **DRAFT / 非规范研究（2026-11-23）。** COS、组织与年代均为架空构想，不是已批准标准、Unicode 或 ISO 10646。本阶段没有实现编码器。

## 字符身份不是编码字节

项目原有 CVL-68 账本把古典拉丁 A 记为十六进制 41，把希腊 Α 记为 80。看似相同的字形具有不同身份；但单字节只能容纳 256 个位置。一个用于全球的字符身份登记簿应先决定有哪些字符，再独立决定如何把身份放入磁盘文件和网络报文。

| 层次 | 责任 |
| --- | --- |
| 字符身份 | 稳定识别文字和符号，独立于字体与网络字节 |
| 存储变换 | 将身份编码为一个或多个字节 |
| 正规化 | 约定组合符号次序、比较与搜索语义 |
| 字形引擎 | 负责连字、重音、位置与打印 |
| 协议 | 显式声明编码格式、版本和记录边界 |

### 三种候选路线

**A. 24 位字符登记号。** 有 2^24 个可编号位置，但登记号宽度不等于每个字符传输时必须占三字节。需要保留号段、不可用码、登记机构和版本政策。

**B. 分平面登记。** 兼顾小设备的常用文字和大型文献库，但必须防止把非拉丁/希腊文字永久设成次等扩展。

**C. 继续为 CVL-68 添加转义页。** 对旧设备友好，但损坏后难恢复、随机访问困难，跨记录边界和状态切换也更复杂。

当前不选定其中一种，也不规定最终的网络变长格式。

## 历史档案如何升级？

原有 CVL-68 字节 52 41 4B 54 45 表示 SALVE。把它们贴上“新编码”的标签不会自动变换其含义；在今天的 ASCII 对照里它们反而看起来像 RAKTE。

安全迁移必须遵守“先按原记录严格解码 → 获得抽象字符身份 → 进行有记录的规范化 → 按明确声明的新格式编码”这一顺序。CVL-54 的 SHIFT/PAD 和机器字打包还需要额外保留页状态、记录边界及来源信息。无法映射的符号必须报错或留存原始数据，不应默默丢弃。

## 语言和政治问题

CVL-68 受古典拉丁与希腊文化影响，不能代表全世界。进入 1990 年代后，汉字、阿拉伯文、印度诸文字、少数民族文字和历史书写体系都需要在登记机构中有适当代表。字符编号政策不仅是 CPU 和硬盘问题，也涉及多文化合作、档案与教育。

Latin A 和 Greek Α 的外观相似问题将扩展到域名、文件名和软件包名，但不应以“统一成同一个字符”作为粗暴解决办法。

## 保留的开放问题

- 字符身份是 24 位整数、分平面整数还是另一种方案？
- CVL-68 字节值是否对应某段连续的新编号？不能凭旧字节表直接推断。
- 哪种存储与网络编码最适合低价 Nova、出版系统和高吞吐服务器？
- 如何把 CVL-68 自定的希腊组合顺序转换到新的正规化方案？
- 一套全球字符标准如何避免以拉丁—希腊的旧文化优势排斥其他语言？
