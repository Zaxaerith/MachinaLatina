# CVL-68 Desktop Typography, 1983–1995
## 希腊—拉丁双文字图形界面的技术问题

> **DRAFT，仅讨论技术接口及软件生态。** 已有 [CVL-68 byte ledger](CVL-68-byte-ledger.md) 尚未冻结，本页所用十六进制字节来自那份候选映射，不是现实 Unicode 或已颁布的国际标准。

## 1. 四个必须分开的层次

**字符编码：** CVL-68 中某一字节（或多字节组合）的字符身份。

**输入设备：** 键盘、输入脚本模式和编辑命令产生上述字符数据。

**文字处理：** 组合记号、希腊末尾 sigma、光标位置、搜索、大小写和归一化。

**排版输出：** 字体轮廓或位图、行距、附加记号定位、纸面几何和打印。

第一层实现了，不代表其余三层已经完成。

## 2. 与既有字符账本一致的测试例子

| 文字 | CVL-68 候选字节 | 关键问题 |
| --- | --- | --- |
| Latin A | 41 | 与 Greek Alpha 不可混同 |
| Greek Α | 80 | 外观相近，字符身份不同 |
| SALVE ΛΟΓΟΣ | 52 41 4B 54 45 20 8A 8E 82 8E 91 | 混合大写文字 |
| λόγος | AA AE B8 A2 AE 98 | 五个希腊字母，六个编码字节 |

在最后一例中，B8 是附着在前一元音上的重音记号，不应被画为独立的等宽字符格。因此光标移动应区分字节边界与可编辑字符簇，删除也需要明确“删除整个字母”还是“只删除附加记号”。

## 3. 原生双文字键盘

建议用户可见的 **LATINA / GRAECA** 输入状态，但不把键盘切换解释为改变文件已有字符。基本模式包括：古典拉丁语 23 字母布局、希腊 24 字母布局、气音/重音组合层及当前脚本状态提示。

附加符号可以“先底字后组合符”输入，或采用其他按键顺序；只有在制定规范后才能断言文件中的唯一保存次序。拼写、词尾 sigma 和大小写规则不得从 Unicode 的现代实现逆向假装成 1980 年代架空设备的既定习惯。

## 4. 编辑器的最低可讨论功能

| 编辑操作 | 必须规定的行为 |
| --- | --- |
| 光标移动 | 按字节，还是按组合字符簇 |
| 删除 | 删除底字、单个重音，或整个字符簇 |
| 搜索 | 精确字节搜索、语言学等价搜索、大小写折叠 |
| 粘贴 | 保持 Latin A 和 Greek Α 的原始字符身份 |
| 文件名 | 避免大小写和外观相近字符造成冲突 |
| 未知字形 | 显示替代图形，不得悄悄删除原始数据 |
| 源码编辑 | 对同形异码标识符给出警告，而非把二者统一 |

## 5. 两种出版技术之争

**位图页输出**：程序自己决定每个点的位置。所见所得较直接，但对打印设备的分辨率和页面尺寸敏感。

**页面描述输出**：程序交付文字身份、字形位置、画线和字体引用等命令。适合更灵活的输出，但打印机需要更复杂的软件、字体存储和排版规范。

两条路线都不能凭借 CVL-68 字符分配自动解决古典希腊语的气音、重音和 iota 下标位置。本项目暂不编造完全规范化的 PostScript 或 PDF 替身。

## 6. 从双文字优先到全球文字冲突

1990—1995 年，若其他文字体系的用户增长，长期只优先支持拉丁语和希腊语的标准将越来越缺乏正当性。未来的全球多文字规范必须讨论统一字符身份、旧文档可读性、组合次序、文件交换和各种地方书写系统，而非把非希腊文字永远视为例外。

真实 Unicode 1.0 在 1991—1992 年的出版史只用于时间参照，并不能自动决定这条架空时间线的国际组织与技术结构。
