# De Codicibus (2005–2026)
## 《代码的世系：分布式协作与自由软件世界》
> DRAFT · 2026-11-26。平台、年代、社会运动和名称为候选架空历史，不是真实 GitHub 或软件发布。真实仓库 MIT / CC BY 4.0 不变。

## 2005–2008：保存文化比追逐新功能更重要
LIBERTAS CODICVM 继承公共档案和科研机构对 CVL/COS 转换、旧数值格式和开放排版软件的需求。机构首先交换源码快照、明确编码和工具链，再建立可追溯版本。宽松许可促进基础库广泛传播；互惠许可推动重要公共系统组件的修改版继续开放。两种制度均可允许商业维护，具体法律条款未定。

## 2008–2012：STEMMA 与分布式源码世系
候选 STEMMA 将原始文件 MATERIA、目录快照 ACTA、修订 EDITIO 分离；修改源码、合并分支、改变来源记录都产生新身份。开发者离线维护本地修订，再向公共机构提出合并建议。COS 中拉丁 A 与希腊 Α 不能自动归为同一个文件；不支持相应名字的操作系统必须明确导出映射或拒绝检出。内容身份不等于作者签名。实际哈希算法、传输和合并算法尚未确定。

## 2010–2015：FORVM CODICVM
建议 FORVM CODICVM 成为一类公共源码托管服务的名称，而非唯一垄断平台。大学档案馆、商业厂商及社区可以维护独立实例，提供仓库镜像、问题讨论、修改提案、审阅、发布索引。候选术语: QVAESTIO (问题), EMENDATIO (修改建议), CENSVRA (审阅), RAMVS (分支), CONIVNCTIO (合并). 术语尚未古典语校订。提案绑定基线和候选修订身份，只有拥有目标分支权限的维护者可接受；基线改变应重新评审合并结果。论坛记录可迁移，代码图独立于托管账号；议题与用户身份迁移协议未定。NODVS/SERMO 可展示审阅页面，但 RETE R1 只有读取操作，发帖/合并需要另行认证写入协议。

## 2011–2018：FASCICVLVS 与设备安装权
同一源码可生成 ORDO-N、PARTES、CVSTOS 的不同包，分别声明 ISA、ABI、依赖、构建来源和发布身份。包管理器不能因为名字或机器字长相同就替换二进制。维护者发布包不代表用户允许程序访问文档和定位。CVSTOS LIBER 候选设备允许用户控制应用信任根和受支持设备的启动信任根，商业锁定设备仍有市场。开放源码、公开构建、安装权限和运行时权限是四项独立的政策。

## 2018–2026：全球开发者共同体
拉丁语可能长期作为标准委员会和系统工具的重要语言，希腊语科研社区维护数值库与专业文献；其他语言社区也用 COS 发布讨论、文档和显示名。不能将拉丁/希腊身份视为贡献资格。初代语言语法和旧文件名限制依然可能给全球贡献者造成成本。包的稳定身份与显示名分离，平台可提示同形混淆但不得自动抹去合法文字。多语议题翻译、独立公共镜像与可重建档案可能形成不同社区文化。翻译和人工智能审阅并不自动证明代码可靠。

三大系统的移植路径：共享 MODVLA 逻辑接口与 COS/NODVS 数据格式；按各自 ISA/ABI 重新构建；使用独立宿主服务；科学代码另用 RATIO 契约评价数值复算。公共科研机构可以要求保留原始数据与明确许可，而不把编译成功当作科学可信性证明。
