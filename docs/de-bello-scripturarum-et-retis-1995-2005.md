# De Bello Scripturarum et Retis (1995–2005)
## 《文字与网络之争：CVL-68、全球字符登记和超文本文明》

> **DRAFT · counterfactual technical history · 2026-11-23.** 本文的机构、标准编号、产品名、发布事件、争议和年份均为架空叙事提案，不是现实历史，也未获项目 CANON 批准。真正发生的历史仅限于明确标注 HIST 的比较材料。本篇纯文档，没有新代码、模拟器、网络协议实现或 CI。

## 序章：一种成功编码，何以成为世界的枷锁？

1968 年，CVL-68 的技术方向解决了古典拉丁语与希腊语在一台机器上共存的困难。1980 年代的 Nova 微机、TABVLA 候选桌面和 Sextaria 学术出版体系依靠这一双文字传统发展。然而，这个优势在国际网络扩张时也形成了路径依赖：一种只能直接表示有限文字的八位字符体系，无法公平承载阿拉伯文、汉字、天城文及许多其他书写系统。

问题更严重的是：CVL-68 的拉丁字母顺序按古典拉丁语 23 字母连续排列。其候选账本中 SALVE = 52 41 4B 54 45；在今天按 ASCII 解释只会看到 RAKTE。这一对照仅用于说明架构差异；我们的架空历史**没有先采用 ASCII 再迁移到 CVL**。不能把现实 UTF-8 的 ASCII 字节不变性直接移植成“CVL 兼容性”。

这一次，争论已不再是“是否给希腊文多分配几个字符”。它必须同时回应三种技术层次：

1. **文字身份：** 哪些字符应被视为独立字符？是否统一拉丁、希腊、汉字、阿拉伯文及各地文字？Unicode 式“字符与字形分离”只是一种现实类比。
2. **存储/传输：** 既有 CVL-68 文件是否可以原样读取？全球字符的网络字节序列、错误检测、记录边界与交换标签如何规定？
3. **网络对象：** 超链接指向的是可编辑文档、排好的纸页、数据库记录，还是它们共同引用的稳定内容对象？

**如果不把这三件事拆开讨论，就会得到一个只是拉丁语换皮的互联网。**

## 现实参照：发生过的事件，而不是本世界的原始文献

- **HIST:** CERN 的首个浏览器/服务器在 1990 年已运行；早期 Web 先有超文本和网络寻址，再经历更复杂的国际化。 [CERN: A short history of the Web](https://home.cern/science/computing/the-birth-of-the-web/short-history-web/)
- **HIST 1995:** HTML 2.0 的 [RFC 1866](https://www.rfc-editor.org/rfc/rfc1866) 发布于 1995 年 11 月。
- **HIST 1997:** [RFC 2070](https://www.rfc-editor.org/rfc/rfc2070) 专门讨论 HTML 的国际化。
- **HIST 1998:** [XML 1.0](https://www.w3.org/TR/1998/REC-xml-19980210/) 作为 W3C 推荐规范，区分文本字符集与结构化标记。
- **HIST 1996/1998/2003:** UTF-8 相关的 [RFC 2044](https://www.rfc-editor.org/rfc/rfc2044)、[RFC 2279](https://www.rfc-editor.org/rfc/rfc2279)、[RFC 3629](https://www.rfc-editor.org/rfc/rfc3629) 体现了真实标准的持续修订；不能把后来的四字节严格规则反投到 1996 年或架空世界。
- **HIST 2003:** [RFC 3490](https://www.rfc-editor.org/rfc/rfc3490) 与 [RFC 3492](https://www.rfc-editor.org/rfc/rfc3492) 处理国际化域名及其 ASCII 兼容传输。
- **HIST 2005:** [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) 讨论 URI 通用语法与百分号编码。架空世界不会被迫使用这些真实协议名和字符表。

## 第一幕（1995—1997）：外来的文字能不能上网？

**DRAFT 1995：** 大学文献交换网络与商业 Nova 服务网络发生第一次公开分歧。CVL-68 可以交换 Latin/Greek 论文标题，某些亚洲和中东合作院校却只能把文档装在二进制附件中，或者临时使用无法统一解释的地方性代码页。

一种虚构但典型的事故：一所地理研究机构把测区的汉字名称编入实验记录，跨校系统仍能传送坐标和地图图像，却不能让收件端以可搜索的文字显示地名。字符失效没有改变文件的物理到达，却破坏了目录和引用。

**拟议的首次标准会议（1996）：** 学术出版社提出先建立跨语言的“字符身份登记簿”，不立即规定唯一网络编码。终端厂商认为应当保留现有 CVL-68 字节；大型出版商则要求一套不依赖终端字体 ROM 的全球文字模型。各方的立场有真正的成本原因，不是“旧人守旧、新人先进”的简单故事。

**DRAFT 1997：** 本项目暂称候选的字符身份方案为 **COS — Codex Omnium Scripturarum**。这个名称和缩写尚待古典语言审查。它可能给予每个字符一个稳定的编号，**而不是**规定所有磁盘和网络必须立刻改用同一种三字节或四字节格式。过去的 CVL 编码是一种来源；某些编号可以为保留旧字符的身份而预留，但**已经发布的 CVL 字节表本身仍是 DRAFT，不能偷偷升级为世界 CANON**。

## 第二幕（1998—2000）：以记录为中心的超文本网络

TABVLA 一类双文字文档系统，与早期 Ordo Operum 的顺序记录文化，可能让架空超文本从**带类型的文献记录**而不是从纯文本标记扩展出来。

**DRAFT 1998：** 研究者提出 **NODVS**（文档节点）和 **LIGAMEN**（链接）作为候选词。每份网络文档先列出身份、文字编码、语言/脚本标签、正文与附件，再把超链接存成独立的、有目标类型的引用关系。这样学术论文中的公式、地图图例、地图数据层和参考书目可以被链接，但不必共享内存或本机文件路径。

与现实 HTML 不同，**初版可以有记录清单、分离正文与导航的模型**；它当然也会面临普通用户用文本编辑器手写页面不便、客户端实现复杂、存储膨胀和浏览器普及受阻的问题。这是一场有实际胜负可能的标准战争，而不是“更高级所以必胜”。

**DRAFT 1999：** 一派网站运营者提出“简化网页”：允许低价 Nova Minor 客户端只读取正文、标题、链接目标，丢弃高级排版对象；另一派坚持 TABVLA 的版式和多文字重音必须被完整呈现。最终可能形成**统一语义、可降级显示**的基础配置，而高级出版附件另有协议。项目尚未确定具体语法或网络报文格式。

**DRAFT 2000：** SERMO（此前历史草案中提出过的文本/网络语言候选）可以从处理 NODVS 文档和服务器目录服务的脚本需求中诞生，但绝不能直接假装它就是改名后的 JavaScript/Python。它的核心课题是**按字符身份搜索、按类型操作记录、处理分离的文档结构**。系统软件编写仍可能由 MODVLA 或其后代承担。

## 第三幕（2001—2003）：同形异码、域名与身份危机

拉丁 A 和希腊 Α 既然早在 CVL-68 起就拥有不同身份，那么随着公网域名开放给希腊语和其他文字，视觉混淆会扩大到网址、证书、登录界面和软件包名称。展示给用户的文字标签与实际用于路由的网络标签需要不同处理。

**DRAFT 2001：** 服务提供者建议采用“全球可显示域名 → 受限制的线上标签”两层设计。建议保留一个经过明确前缀与可逆算法约定的保守字符子集，供老式名称解析服务传输。前缀、数值编码和冲突检查都没有标准化，**不能把现实 Punycode 名称贴到本世界的域名算法上**。

**DRAFT 2002：** 某出版社发现两个看起来相同的大学图书馆网站标识，内部一个用了 Latin A，另一个用了 Greek Alpha。由此催生域名注册时的脚本告警、混合脚本审核和可见源脚本提示。单纯把两个字符视为等价会破坏合法的希腊文和拉丁文，因此处理必须有地域和语言政策。

**DRAFT 2003：** 网络安全机构要求每个文档的字节编码与字符身份版本必须在传输层或内容描述符中明确；不得先用启发式猜测再默默归一化。转码失败应报告损坏或未知字符，不应自动丢掉汉字、气音或科学符号。

## 第四幕（2004—2005）：标准战争没有绝对赢家

即使世界通用字符登记簿出现，互联网上仍然可能同时存在三种文档：
- 传统 CVL-68 字节文本；读写成本低，保留已有学术档案。
- COS 字符身份的国际多文字语义文档；跨语言检索、自动翻译与学术引用方便，但解析成本更高。
- 带有严格版面元数据或页面附件的出版文档；适合精确复现科学公式和地图图注，但体积、可编辑性和可访问性面临争论。

**DRAFT 2004：** 两种服务器系统开始竞争：一派强调极简正文与稳定链接，能够在旧 Nova 上廉价部署；另一派强调丰富 NODVS 类型、科研数据、学术排版及 Sextaria 科学计算后端。服务器架构沿袭了三大机器家族的**软件传统**，但不等于所有服务器都真的使用 48 位 CPU。

**DRAFT 2005：** 国际网络协会就“世界字符身份优先，历史字节编码通过声明保留”的原则达成候选妥协。将旧字节直接重解释为新编码的做法被拒绝；网络上的多文字文档采用显式的编码标识与严谨转码。究竟采用定宽、变长或多种并存的交换编码，留待后续技术标准文档进一步比较，不在本叙事中伪装成已冻结的互联网 ABI。

## 五场仍未结束的争论

| 分歧 | A 路线 | B 路线 | 历史后果 |
| --- | --- | --- | --- |
| 字符身份 | 继续扩展 CVL-68 代码页 | 建立独立全球字符编号 | 全球文字与古典语言制度的冲突 |
| 网络编码 | CVL-68 外层继续扩展 | 全新多字节传输格式 | 文本兼容和存档长期维护 |
| 文档 | 排版/页面优先 | 语义结构与记录优先 | 出版商与 Web 开发者竞争 |
| 域名 | 原始国际文字直接注册 | 显示名称与受限网络标签分层 | 地址稳定性、安全与文化公平 |
| 服务器 | Nova 低成本服务 | 科学/出版端高类型系统 | 内容服务与算力、应用平台分离 |

**推荐的研究方向是折中，而不是任意一派消灭其余派别。** 历史标准通常背负既有投资；没有人能让几十年的字节和数据记录凭空消失。

## 后续世界史的挂钩

2005 年之后需要研究：浏览器安全与国际文字域名，服务器端动态语言，开放源码许可证和软件分发，互联网搜索与索引、科学数据互联，以及从移动互联网发展到 2015—2026 年机器学习模型对世界文字的处理方式。

我们的架空世界可能从一开始就把 Latin/Greek 视为核心，却也必须在跨文化全球化面前发现这种制度的局限。这里的制度史，比给某一种现实技术改拉丁名字更加重要。

### Status / 可引用边界

- **CANON：** 古典拉丁语持续活用，希腊语在科学制度上有重要地位；CVL-68 作为八位双文字主流的技术方向。
- **DRAFT：** COS、NODVS、LIGAMEN、所有 1995—2005 年的机构、事件、名称、标准路线及网络胜负。
- **HIST：** 真实 CERN、RFC、W3C、Unicode 的日期只用作技术约束与事实比较。
- **未交付：** 网页语言语法、浏览器、网络服务端、字符转码器、全球标准化测试程序和 CI。
