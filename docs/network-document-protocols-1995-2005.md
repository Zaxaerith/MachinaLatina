# NODVS / LIGAMEN / RETE — A Typed-Record Internet (1995–2005)
## 超文本文档、网络地址和多文字域名的候选研究

> **DRAFT / 非规范架空技术研究。** NODVS、LIGAMEN、RETE 均为暂用拉丁技术词。不是已发布协议、实际 HTTP/HTML/XML 替身，也没有实现浏览器或服务器。

## 从 TABVLA 与 Ordo 继承了什么？

1980 年代的 TABVLA 候选文档系统重视页面结构，Ordo Operum 的研究性批处理协议强调带长度的记录。它们提供了一条可能不同于纯标记文本的互联网路线：

- NODVS：有稳定标识和内容类型的网络文档节点；
- LIGAMEN：从一个节点指向另一个节点或节点内部对象的引用；
- RETE：提供地址解析、内容描述、传输和缓存的网络层概念。

名字不代表已经决定单一技术组织、报文结构或语法。

## 第一代“有类型的网页”

假设一份科研文档至少描述：

| 属性 | 作用 |
| --- | --- |
| 文档标识 | 网络上稳定区分对象，不能是本地文件路径 |
| 正文类型 | 纯文字、结构化文字、页面附件、数据表等 |
| 字符身份/编码声明 | 明确 CVL-68 或未来 COS 转换格式 |
| 语言与脚本 | 区分正文语言、源代码标识符和字体要求 |
| 记录长度 | 在二进制与字符层面明确边界 |
| 链接关系 | 指向目标节点、数据记录或引用位置 |

**故意暂不定义封包字节。** 标识符的数字表示、长度字段、压缩、端序、错误恢复与内容协商都必须独立决定。不能把 OMR1 现代实验档案宣称为 1998 年网络线协议。

候选优势：有利于文献引用、地图和科学数据、不同版式的语义复用。候选劣势：文档难以用简单文本编辑器手写，浏览器解析代价大，跨版本的对象引用和缓存一致性复杂。很可能出现“轻型 Nova 网页”和“出版型 TABVLA 文档”两种分支。

## 为什么不直接把 HTML 改名？

现实 HTML 从标记和超链接出发形成历史路径，而架空世界若真的继承了强势的记录与学术出版传统，就可能强调节点、记录清单和独立附件。唯一确定的是两条路线都有不同成本；不能在还没定义语法的情况下宣称架空设计比真实 Web 更好。

## 域名与同形异码风险

项目 CVL-68 把 Latin A（41）和 Greek Α（80）视为两个字符。国际化域名进入大众浏览器后，同形字符可能让不同的网络名称在视觉上混淆。

一种可研究的折中方案是：

1. 用户看到自己熟悉的多文字标签；
2. 名称服务中维护经脚本及正规化检查的抽象字符标识；
3. 旧解析器使用**明确前缀、可逆、字节安全**的保守标签编码；
4. 显示端对跨文字体系的混写提供提醒；
5. 只有发生明确规范化规则下的等价时，才将两个标签判为相同。

前缀、可逆映射、保守字母表、允许字符与检测规则全部尚未决定。特别是旧 CVL-68 文本数字与现实 ASCII **不共享完整字母表字节顺序**；若在线协议依靠特定字节值实现互通，必须自行公布其线路字节契约。不能悄悄复制现实 RFC 3492 的 Punycode 算法并称之为本世界自然产物。

### 科学文件与普通页面的差别

一份地理科研网络文档可能同时有拉丁语说明、希腊公式、图幅、地名和栅格数据。若它提供的链接只指向图片而不描述数据层、比例尺与坐标参照，则信息无法被可靠复用；若要求所有浏览器理解高级科学对象，又会阻碍低成本 Nova 普及。

一个可信的兼容策略是“基础节点可显示文本与引用，高级对象通过类型化附件交给专用程序”，但仍需规定未知对象的跳过和引用保持规则。

## 1998—2005 候选标准分裂

| 竞争路线 | 优点 | 风险 |
| --- | --- | --- |
| 易手写的轻量文本标记 | 门槛低、传输直观 | 高级文档结构和二进制引用不统一 |
| 类型化记录与对象链接 | 科研数据、复合文献、文档元数据更稳定 | 编辑和实现复杂，低价终端不友好 |
| 固定页面附档 | 视觉再现可靠 | 检索、可编辑性和可访问性可能较差 |

一场架空互联网标准之争很可能产生多格式共存，而不是胜利者突然统一全世界。

## 未解决问题

- 域名的正式字符集和线路标签算法；
- 节点标识、内容定位和网络寻址的关系；
- MIME 类内容标记的架空替代品是否需要存在；
- 浏览器文本解析、缓存、版本协商与安全边界；
- 大小写与跨文字相似字母的显示策略；
- 网络文件与原 XXXVI/Sextaria 二进制程序的互换边界；
- SERMO 是否诞生为面向 NODVS 的脚本语言（DRAFT，不是改名 JavaScript）。
