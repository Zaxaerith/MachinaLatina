## Four traditions

**TRANFOR**: formula calculation and scientific batches evolve toward libraries, arrays and reduction contracts. A common source expression does not make XXXVI and Nova binaries compatible.

**MODVLA**: the 36-, 32- and 48-bit machines motivate separation of logical values, local storage, external records and native ABI. Later private module state, opaque handles and interface dispatch may compete with class inheritance. GUI object libraries need not dictate kernel design.

**RATIO**: a scientific result declares units, arithmetic format, operation order, reference and tolerance. Later profiles could wrap TRANFOR routines with verification and evidence records, without proving observations or physical models true.

**SERMO**: typed document construction starts in library/publisher servers, with later optional client runtimes, closures, event handling and managed immutable text. Passive NODVS records remain passive; host publication requires independent authority.

## Paradigm disputes

1986–1995: DOMESTICA application vendors might favor object composition for GUI, OFFICINA system developers static module interfaces, ACRIBIA scientific teams pure operations. These are fictional incentives, not product claims. Indirect calls, layout and interface evolution have costs. Multiple inheritance is not inevitable.

1996–2015: SERMO may favor tracing GC, reference counting or bounded arenas; collection does not guarantee timely release of files or grant authority. MODVLA may retain explicit resource lifetimes. RATIO can favor scoped scratch storage and reproducible operation order.

2016–2026: a later MODVLA profile could distinguish unique writable access, shared read-only views and explicit transfer, building on LOCVS/FENESTRA/TESSERA studies. Borrow checking, reference counting and region inference compete. A handle is not an address; memory safety is not an OS permission model. Atomics, races, DMA, device fences and formal lifetime rules remain open.

Functional approaches could develop from pure SERMO operations and RATIO expression graphs. Greek mathematical scholarship can influence educational notation, not the underlying laws of computation. Neither R1 defines a complete functional language or recursion.

## Two scripts, not two incompatible languages

Latin is a living technical lingua franca; Greek retains institutional scientific weight. The 23-letter classical core is a compatibility convention, not a claim about all everyday Latin. CVL-54 is stateful; CVL-63/TP1 adds parity rather than characters; CVL-68 is native eight-bit; COS-97 separates character identities from serialization. No ASCII or Unicode numerical identity substitution.

A proposed post-1997 scholarly profile may permit Greek identifiers with an explicit lexical profile, registry revision, import aliases and a normalization policy still to be settled. Latin A and Greek Α remain distinct. No automatic transliteration or implicit keyword synonyms. A Greek mathematical frontend could lower to shared typed intermediate representation without sharing syntax or ABI. Other scripts remain important: COS storage alone does not guarantee equitable education, tooling or model tokenization.

## 2026 developer workflow

A hypothetical Nova developer uses MODVLA to encode and transport records, TRANFOR for numerical kernels, RATIO for independent tolerance checks, SERMO for interactive documents. STEMMA and FASCICVLVS associate revisions and target artifacts, not universal binaries. PARTES needs its own IPC adapter, CVSTOS scoped services. MENTIS code suggestions do not establish successful compilation or numerical evidence.
